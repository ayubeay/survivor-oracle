# 0.4.5 - LP lock is not measured, and no longer pretends to be

**Date:** 2026-08-02 · **Score impact:** none. Reporting and coverage only.

## What was wrong
fetchTokenData returned a hardcoded lpInfo of { locked: false, lockDuration: 0,
percentLocked: 0 } for every non-megacap token. No RPC call, no rugcheck lookup, no data
source of any kind. scoreLpLocked then read locked: false and returned 0 on a 20-weight
signal.

Every token in the system carried a 20-point penalty for an unlocked liquidity pool that
was never checked. The paid report stated "lp: locked false, percent_locked 0" as though
it were an observation.

Third instance of the same pattern, after the holder-concentration denominator and the
dev-activity default: a constant presented as a measurement.

## Fix
- lpInfo is null when unmeasured. No fabricated object.
- scoreLpLocked returns null rather than 0 when there is nothing to score.
- coverage excludes lpLocked, dropping observed coverage from 85% to 65%.
- /report will report LP status as unknown rather than asserting an unlocked pool.

## Why no score moved
The scorer still sums contributions over a fixed 100-point denominator. Excluding a signal
that contributed 0 changes nothing arithmetically. The 20-point hole remains; it simply no
longer claims to be evidence.

Verified across BONK, mSOL, JUP, WIF and POPCAT: all unchanged, all now at 65% coverage.

## Doctrine
Absence of LP-lock data is not evidence that liquidity is unlocked. Until a reliable
LP-lock source and an applicability model exist, the signal remains unmeasured and
contributes neither positive nor negative evidence.

## Deferred to 0.5.0, deliberately
Naive renormalization would divide by measured weight: mSOL's 59 at 65% coverage becomes
roughly 91. A token we know less about would score better than one we know more about.
That is a worse failure than the current silent penalty.

Three policies to compare across a broad sample before choosing:
  1. fixed denominator (today) - hidden penalty for unmeasured signals
  2. full renormalization - rewards low coverage
  3. evidence score plus coverage-constrained gate - separates "how good is what we
     measured" from "how much did we measure", and caps the gate decision when coverage
     is thin

The third looks strongest: an evidence score of 91 at 65% coverage should not reach ALLOW.
Risk quality and evidence completeness are different dimensions and should not be collapsed
into one number.

## Open, related
LP applicability by asset class is a separate question. A liquid staking token has no
memecoin-style locked pool, so even a working LP data source would need to distinguish
"unlocked" from "not applicable". Asset class is not derivable from the chain, which puts
that classification in Layer 2 alongside program governance.
